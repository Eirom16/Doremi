# Technical Documentation: Doremi Architecture

## 1. Rust / C++ / Qt Architecture
Doremi uses a hybrid architecture combining the safety, reliability, and performance of Rust with the modern desktop UI capabilities of Qt Widgets via C++.

- **Rust Core**: Responsible for network calls, parsing the YouTube Music API, audio streaming via VLC, D-Bus/MPRIS integration, local SQLite database management, and configuration persistence.
- **C++ UI Layer**: Implements a responsive, animated desktop user interface using Qt6 Widgets.
- **CXX Bridge**: Safe, type-defined boundaries between C++ and Rust are generated by `cxx`.

### Component Design
To keep `DoremiMainWindow` thin and maintainable, logic is divided into specialized controller classes:
1. `ShortcutManager`: Handles setup and wiring of global application hotkeys (Play/Pause, volume delta, seek, navigation).
2. `TrayController`: Integrates the app with the system tray icon, notification daemon, and tray actions context menus.
3. `NavigationController`: Manages routing history, forward/backward stacks, and persists scroll/focus state across views.
4. `SessionCookieManager`: Captures and filters Google/YouTube cookies from the embedded WebEngine context and propagates auth state to the Rust backend.
5. `ThemeController`: Manages the accent color stylesheet application and transitions between Dark and Light modes.

## 2. Signal Flow between UI and Core
Communication operates in both directions:
1. **C++ to Rust (User Actions)**: 
   User interactions (e.g., clicking play, typing a search query) trigger Qt signals. The connected slots call global functions generated by CXX (e.g., `on_play_pause_triggered()`), which delegate to the corresponding Rust services (e.g., `PlayerService`).
2. **Rust to C++ (Backend Updates)**:
   When Rust services complete an operation (e.g., loading search results, updating track progression), they invoke the corresponding C++ bridge function (e.g., `set_search_results()`). These FFI calls run safely on the Qt GUI thread using the thread-safe dispatcher function `mutate_main_window`.

## 3. How to Add a New View
1. **Define the View class**: Create `<new_view>.h` and `<new_view>.cpp` inheriting from `QWidget`.
2. **Implement Theme Updates**: Make sure it implements `update_theme()` using colors from `DesignTokens::current()`.
3. **Register in MOC & Compilation**: Add your header to `moc_headers` and source to `cpp_sources` in `build.rs`.
4. **Instantiate inside `DoremiMainWindow`**: In `main_window.cpp`'s constructor, instantiate the view and add it to the `stack_` stacked widget.
5. **Update Routing**:
   - In `navigation_controller.cpp`, add the route mapping (set the correct stacked widget index).
   - In `NavSidebar`, add the navigation button if needed.

---

## 4. How to Add a New C++ Component
1. Create `components/<component_name>.h` and `components/<component_name>.cpp`.
2. Register it in `build.rs` under `cpp_sources` and `moc_headers` (if it uses `Q_OBJECT`).
3. Apply styling using `DesignTokens` to ensure theme compliance.
4. Use `DesignTokens::applyAccessible(...)` to specify accessibility properties and tooltips.

---

## 5. How to Use `DesignTokens`
`DesignTokens` centralizes colors, margins, fonts, and animation durations. Do not hardcode hex colors or sizes.
- **Get Colors**: Use `DesignTokens::current().bg_surface`, `DesignTokens::current().accent`, etc.
- **Get Fonts**: Use `DesignTokens::getFont("body")`, `DesignTokens::getFont("heading_lg")`, etc.
- **QSS Helpers**:
  - `DesignTokens::textStyle("heading_sm")`
  - `DesignTokens::panelStyle("surface", 12)`
  - `DesignTokens::scrollAreaStyle()`

---

## 6. Visual Test Mode & AI Screenshots
Doremi supports a command-line interface for visual validation and screenshots:
```bash
cargo run -- --ui-test <view> --screenshot /path/to/save.png
```
Supported views: `home`, `search`, `library`, `now-playing`, `settings`.

### How it works:
1. **Mock Data**: Bypasses the YouTube authentication and checks, loading fake metadata (such as long/short titles, empty states, 37% progress download) using `crate::utils::mock_data`.
2. **Fixed Canvas**: Opens the UI window at a strict size of `1300x820`.
3. **Screenshot Capture**: Waits for `2500ms` for the layout to settle, grabs the pixel buffer using Qt's `grab()`, saves the image, and terminates.
